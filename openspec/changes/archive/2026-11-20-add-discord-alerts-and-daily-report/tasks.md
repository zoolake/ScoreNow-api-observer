# 구현 작업

## 1. 공통 디스코드 전송

- [x] 1.1 운영 환경에서 웹훅 URL을 주입하고, 실시간 요약과 보고서 첨부를 지원하는 공통 전송 기능을 추가한다. 대체 HTTP 클라이언트로 첨부 형식, 응답 확인, 시간 초과와 민감 정보가 제거된 오류 로그를 검증한다.

## 2. KST 일간 운영 보고서

- [x] 2.1 `auto-watch-status`의 로컬 기록 로딩과 종목 분류를 재사용해 일간 집계를 추가한다. 요청 시도 수, 실패 유형, 정각 구간별 최고 사용률과 예외 종료를 집계하고 KST 자정 경계, 기존 요청 기록 호환, 부분 읽기 실패를 테스트한다.
- [x] 2.2 같은 집계에서 디스코드 요약과 Markdown 상세를 만들고 파일을 먼저 저장한다. 발행 명령은 기본으로 전날 KST를 사용하고 날짜를 지정하면 저장된 보고서를 재발행할 수 있게 한다. 대체 전송으로 첨부 생성, 실패 후 재발행, 성공한 자동 발행의 중복 방지와 BETS API 무호출을 검증하고 사용 방법을 문서화한다.
- [x] 2.3 별도 systemd 서비스·타이머를 `deploy/systemd`에 추가한다. Linux에서 `systemd-analyze verify`로 단위를 확인하고 `systemd-analyze calendar`로 매일 `00:00:00 UTC`가 오전 9시(KST)에 해당하는지 검사한다. 배포 문서에 발행 시각, 누락 날짜의 수동 발행과 타이머 상태 확인 방법을 정리한다.

## 3. 실시간 운영 알림

- [x] 3.1 Auto-watch 결과에서 수집 중단, 반복 실패·복구, 응답 경기 누락과 경기별 예외 종료를 알린다. 주기별 횟수 경계, 반복 발송 방지, 예외 저장 성공 후 발송과 전송 실패 시 기존 수집 정책 유지를 검증한다.
- [x] 3.2 `time_status` 특이값과 `3 → 1`, 축구 연장·승부차기, 야구 연장 이닝 알림을 추가한다. 대체 응답으로 시간 미정 지속 조건, 축구 연장 후반 최초 관측, 야구의 경기별 정규 이닝 수, 재시작 후 같은 경기 알림 재발송 방지를 검증한다.
- [x] 3.3 Auto-watch 밖에서 마지막 처리 시각과 현재 요청량을 점검하도록 연결한다. 기록이 오래된 경우, 이미 알린 동일 중단, `80%`·`90%` 경계와 다음 정각 구간을 검증한다. 운영 문서에 기본 임계값, 알림 설정과 점검 명령을 기록한다.

## 4. 통합 검증

- [x] 4.1 저장 기록과 대체 웹훅으로 정상 수집, 운영 알림과 오전 9시 일간 발행을 함께 검증한다. 기존 요청 전 기록 저장과 재시작 정책이 유지되는지 확인하고 Ruff 검사·포맷 검사, Pyright, pytest를 실행한다.
