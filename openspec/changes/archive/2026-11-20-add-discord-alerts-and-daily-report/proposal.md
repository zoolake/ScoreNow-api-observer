# 제안서

## Why

관리자는 수집 중단이나 경기 데이터 누락을 확인하려면 서버 로그와 저장 기록을 직접 살펴봐야 한다. 디스코드에서 대응이 필요한 상황을 알리고, 하루 동안의 요청량과 수집 예외를 한 번에 확인할 수 있게 한다.

## What Changes

- 수집을 중단시키는 HTTP `401·402·403·429`, 운영 설정 및 저장 오류를 즉시 알린다. 연결 오류와 `5xx`는 반복될 때 알리고, 장애가 해소되면 복구를 한 번 알린다. Auto-watch 처리 주기가 멈춘 경우에는 프로세스 밖에서 마지막 처리 시각을 확인해 알린다.
- 정상 HTTP 응답에서도 수집 대상 경기가 반복해서 빠지거나 여러 경기가 한꺼번에 누락되면 알린다. 경기별 관찰 상한에 도달해 수집을 예외 종료한 경우에는 경기와 종료 사유를 알린다.
- 종목별 요청량이 현재 정각 구간의 경고·위험 기준을 처음 넘을 때 알린다. 기존 `80%`·`90%` 설정을 사용하고, 현재 구간에 유효한 API 잔여량이 있으면 로컬 요청 수와 함께 표시한다.
- Event View의 `time_status`에서 `0·1·3` 이외의 값과 `3 → 1` 전이를 알린다. `2`(시간 미정)는 오래 지속될 때 알리고, 연기·취소·경기 중단 등 나머지 특이 상태와 `3 → 1`은 처음 관측할 때 알린다. 같은 상황의 반복 관측은 하나의 알림으로 묶는다.
- 축구는 `timer.md`의 `2`(연장 전반), `3`(연장 후반), `4`(승부차기)를 사용한다. 경기별로 `2` 또는 `3`을 처음 관측했을 때 관측된 구간을 알리고, `4`를 처음 관측하면 승부차기 진입을 알린다. 야구는 경기 중 `extra.numberofperiods`를 초과하는 이닝의 점수가 처음 관측될 때 경기당 한 번 알린다.
- 디스코드의 첫 발행 보고서는 **KST 일간 운영 보고서**로 한다. 전날 KST 00:00부터 당일 KST 00:00 직전까지의 로컬 기록을 집계한다. 엔드포인트별 요청 시도 수, 종목별 시간당 최고 사용률, HTTP 오류·연결 실패·완료 기록이 없는 요청, 상태값별 수집 예외 종료 건수를 담는다. 예외 상세에는 경기 ID·리그·종료 시각을 표시하고, 일부 기록을 읽지 못했으면 요약에도 표시한다.
- 일간 보고서는 매일 오전 9시(KST)에 별도 예약 작업으로 생성하고, 디스코드 메시지에 요약 카드와 상세 Markdown 파일을 함께 발행한다. 전송에 실패하면 저장된 보고서를 재발행할 수 있게 한다.
- 예정 경기 탐색 누락과 주요 응답 필드의 구조 변화는 실시간 알림 범위에서 제외한다.

## 기능

### 신규 기능

- `discord-operations-alerts` — 수집 오류와 복구, 요청 한도, 경기별 수집 및 경기 상태에 대한 디스코드 실시간 알림.
- `daily-operations-report` — KST 일간 요청·오류·예외 집계와 디스코드 요약 및 상세 보고서 발행.

### 변경되는 기능

## 영향 범위

- Auto-watch의 수집 결과와 상태 전이, 공통 BETS API 요청 기록, 경기별 예외 기록을 사용한다. 일간 집계는 `auto-watch-status`가 읽는 로컬 기록을 재사용한다.
- Oracle VM의 예약 작업과 디스코드 웹훅이 발행에 관여한다. 웹훅 URL은 운영 환경에서 비밀로 관리한다. 알림 및 보고서 발행을 위한 추가 BETS API 호출은 필요 없다. 디스코드 전송 실패와 기존 수집의 중단·재시작 판단은 서로 독립적으로 처리한다.
